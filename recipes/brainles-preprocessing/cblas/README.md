# Native CBLAS feasibility build

The ARM recipe runs `build-native.sh` after the original packages, patches, and assets. The operation installs a rebuilt Torch into that same image before the existing archive and SIF conversion. The original fulltest and deployment checks remain unchanged. Release status is `DIAGNOSTIC_BLOCKED` and `merge_eligible=false`, including after successful science. The intentional ARM gate remains.

Recipe variables render `pins.json`. Declared files supply every script, header, provider wheel, Debian package, and Python wheel through `get_file`. The compiler package closure was resolved for Ubuntu 24.04 ARM with APT from an empty package status. GCC and G++ are 13.3.0, Debian revision `13.3.0-6ubuntu2~24.04.1`. Offline APT installs the exact declared closure and refuses package removals. The build checks every installed package revision. No package resolver uses a network index during this operation.

The Python build environment uses the original Python 3.11 interpreter with separate packages. Its pinned tool wheels include CMake 3.31.6, Ninja 1.11.1.4, SCons 4.7.0, NumPy 2.0.1, and the pinned Torch build requirements with their dependencies. Interpreter, headers, library, compiler, and wheel ABI checks guard the separation. The runtime installation replaces only Torch with `--no-index --no-deps`. Package inventories must match except for Torch, and the original runtime NumPy constraints remain.

Torch and ACL are ordinary HTTPS Git checkouts at exact commits. Recursive gitlinks supply Torch's nested sources. Root and nested repositories must be clean and initialized. Git transport is uncached. No research cache or reconstructed Git metadata is an input to CI. Fixed tool artifacts use dependency digest sources. Updating their versions requires resolving a new compatible closure, including filenames and the recipe's rendered tool inventory.

The operation preserves the reviewed ACL and Torch flags. It uses the supported explicit `DNNL_BLAS_VENDOR=OPENBLAS` CMake definition and the project include hook in `provider.cmake`. The generated cache and GEMM command must select the expected provider and header directory. The checker preserves separated and joined `-I` and `-isystem` handling. The public CBLAS header uses the pinned upstream installation substitution. Its LP64 config header wraps the pinned public template. These are reconstructed ABI declarations, not recovered original wheel-builder headers.

Two compiler jobs and a 480-minute operation deadline with 60 seconds of termination grace bound requested concurrency and time. Resource records describe the actual RUN view, with hidden ancestry and required capacity unknown. No finite memory ceiling, disabled swap, privileged operation, or absolute job-clock reservation is provided. The 720-minute job and original 80 minutes of test command deadlines leave at most 159 minutes for all remaining work. Completion within that budget is unproven.

On success, `/opt/brainles-cblas-evidence` retains the wheel, rendered pins, logs, configuration, package inventories, source identities, ELF records, and installed library mappings. Provider libraries and built ACL libraries are copied into Torch before build paths are removed. A subsequent import verifies the source commit, version, provider hashes, and actual loaded provider paths. These records travel inside the image archive and SIF. Existing workflow tools retain ownership of their artifact identities and scientific results.

Ordinary failures preserve the original exit status and emit bounded log excerpts, available configuration, and the current phase to CI stdout. Failed RUN files are not exported as host artifacts. KILL, timeout, runner loss, and conversion failure can prevent final records or uploads. An exit status alone is never labelled OOM. There is no fallback wheel or successful diagnostic image on failure.

This integration has no native configure, build, import, linkage, science, or performance result. Missing original wheel flags, cache, ACL override, and historical running-provider hash prevent a pure one-variable comparison. The unchanged SIF suite must establish actual default-device extraction, checkpoint and model identity, voxel and geometry checks, input and weight immutability, the original fixture, two threads, and the 600-second deadline. A separately reviewed release change is required before merge eligibility.
